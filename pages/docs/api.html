REST API

2030B Auth API

The same backend that powers 2030B is a public REST API. Use it to embed the 2030B sign-in popup on any of your sites, read user data with consent, and integrate the credit system.

Intro

Base URL: https://2030b.com/backend/api.php

All endpoints return JSON. POST endpoints require a CSRF token (?op=csrf) in X-CSRF header. Cross-origin requests need a valid API key in X-API-Key.

Authentication

Two auth modes:

  • Session — the user logs in via the popup, a B30SESS cookie is set, follow-up requests reuse it.
  • Key — partner sites pass X-API-Key: b30k_… on every request. Each key is scope-restricted (auth:read, auth:popup).

API keys

Manage your keys at /pages/api-keys.html. Each key has:

  • id, label, key (the secret).
  • scopes — array of auth:read, auth:popup, …
  • origins — array of allowed domains (CORS), or ["*"].
  • enabled — boolean.

Super-admin can revoke any key at any time from the admin panel.

Embed snippet

Drop this on any HTML page:

<script src="https://2030b.com/auth/embed.js" data-key="b30k_YOUR_KEY"></script>

<button onclick="B30Auth.open()">Sign in with 2030B</button>

<script>
  B30Auth.on('signin',  user => console.log('signed in', user));
  B30Auth.on('signout', ()   => console.log('signed out'));
</script>

REST endpoints

All endpoints use ?op=.... Mutating endpoints require X-CSRF.

Public

GET ?op=csrf — issues a CSRF token.
GET ?op=providers.list — list all P2P providers.
GET ?op=security.public — public security policy (password min, max upload size, etc.).
GET ?op=penalties.cfg.public — penalty rules.
GET ?op=ecosystem — ecosystem currencies + rates.
GET ?op=fx — FX rates (USD base).

User auth

POST ?op=register — {email,password,full_name,country_code?,language?,ref_code?}
POST ?op=signin — {email,password}
POST ?op=signout
GET ?op=user.me — current user info.
POST ?op=user.profile.update
POST ?op=user.verify_email — {code}

Pairing & ops

POST ?op=pairing.create — multipart: platform, buy_usdt, buy_fiat, buy_currency, buy_date_ts, sell_usdt, sell_fiat, sell_date_ts, buy_file, sell_file
GET ?op=pairing.list
POST ?op=op.create — single-leg op: platform, type(buy|sell), amount_usdt, amount_fiat, fiat_currency, transaction_date, op_file

Errors

rate_limited429per-bucket rate-limit hit

server500internal error (see message field)

Rate limits

Per-bucket per-minute limits from security.json > rate_limits:

  • signin_per_minute — default 5
  • signup_per_minute — default 3
  • admin_per_minute — default 30
  • api_per_minute — default 120

Examples

curl

# 1) Get CSRF token (sets B30SESS cookie)
curl -c jar -b jar 'https://2030b.com/backend/api.php?op=csrf'

# 2) Sign in
CSRF=$(curl -sS -c jar -b jar 'https://2030b.com/backend/api.php?op=csrf' | jq -r .token)
curl -sS -c jar -b jar -X POST \
  -H "Content-Type: application/json" \
  -H "X-CSRF: $CSRF" \
  -d '{"email":"me@example.com","password":"secret123"}' \
  'https://2030b.com/backend/api.php?op=signin'

# 3) Me
curl -sS -c jar -b jar 'https://2030b.com/backend/api.php?op=user.me'

JavaScript (fetch)

const API = 'https://2030b.com/backend/api.php';
const KEY = 'b30k_YOUR_KEY';

async function api(op, body, method='GET') {
  const t = await fetch(API+'?op=csrf', {credentials:'include'}).then(r=>r.json());
  const r = await fetch(API+'?op='+op, {
    method, credentials:'include',
    headers: { 'Content-Type':'application/json', 'X-CSRF': t.token, 'X-API-Key': KEY },
    body: body ? JSON.stringify(body) : undefined
  });
  return r.json();
}

await api('signin', {email:'me@example.com', password:'secret123'}, 'POST');
const me = await api('user.me');
console.log(me);
